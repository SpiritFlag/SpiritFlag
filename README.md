## 🧠 How I Work

### ⚙️ SCBP — 개발자 사용 설명서

저는 **Single-Core Batch Processor**입니다.

한 번에 하나를 깊게 처리하고, 끝나면 다음 일을 꺼냅니다.  
멀티코어가 아니라서 느려 보일 수 있지만, **한 코어가 꽤 셉니다.**

#### ✅ 이렇게 해주세요

- **일감은 하나씩, 순서대로.** 큐에 넣어두시면 알아서 꺼내 씁니다.
- **"왜"를 같이 알려주세요.** 맥락이 있으면 알아서 확장합니다.
- **결과물은 문서로 드립니다.** 읽으면서 웃으셔도 됩니다. 의도된 겁니다.
- **끝났다고 하면 진짜 끝난 겁니다.** 운영과 검증까지 보고 말하는 편이라서요.

#### ⚠️ 이런 건 어려워요

- **동시에 세 가지 물어보기** — 셋 다 답은 나오는데, 세 번째는 좀 걸립니다.
- **진행 중인데 방향 바꾸기** — 컨텍스트 스위칭 비용이 큽니다. 대신 바꾸기로 하면 깔끔하게 바꿉니다.
- **"적당히 해줘"** — 적당히가 안 됩니다. 범위를 정해주시면 그 안에서 끝까지 갑니다.
- **이름을 대충 짓기** — 파일명, 자산명, API 필드명... **이름은 약속입니다.** 이건 오래된 병입니다.

### 🚗 Spark — 함께 만드는 개발

AI에게 코드를 맡기는 시대입니다.

그런데 어느 순간 깨달았습니다.  
**AI가 모든 걸 알아서 만들어준다면, 정작 개발자인 저는 뭘 하고 있는 걸까요?**

저는 개발을 외주 맡기고 싶은 게 아닙니다.  
**함께 고민하고, 직접 선택하고, 만드는 과정까지 즐기고 싶습니다.**

그래서 제 개발 방식에 `Spark`라는 이름을 붙였습니다.

**Plan → Design → Implement → Deploy**

- 💭 **Plan** — 무엇을 만들고 싶은지 자유롭게 이야기합니다. 처음부터 정답이나 완벽한 기획서가 필요하지는 않습니다.
- 🧭 **Design** — 기술적인 선택과 대안을 함께 고민합니다. 중요한 결정은 직접 이해하고 참여합니다.
- 🛠️ **Implement** — 합의한 방향으로 실제 동작하는 것을 만듭니다. 더 좋은 방법이 발견되면 유연하게 바꿉니다.
- 🚀 **Deploy** — 결과를 정리하고 실제 사용할 수 있는 상태로 마무리합니다.

이 네 가지는 반드시 순서대로 통과해야 하는 관문이 아닙니다.  
**개발을 돕기 위한 흐름이지, 개발을 통제하기 위한 절차가 아닙니다.**

> **함께 생각하고, 자유롭게 만들고, 실제 결과로 판단한다.**

### 🤖 Working with AI

AI 시대라고 해서, 그냥 던진다고 일이 되지는 않습니다.  
**던져봤습니다. 안 됐습니다.**

AI는 단순한 코드 생성기가 아니라, 함께 문제를 해결하는 개발 동료가 될 수 있다고 생각합니다.

- 🤝 **AI는 동료입니다.** 서로 의견을 제시하고 토론합니다. AI가 항상 맞는 것도, 제가 항상 맞는 것도 아닙니다.
- 🧭 **맥락이 먼저입니다.** 무엇을 왜 만드는지 이해해야 올바른 구현이 가능합니다.
- 🎚️ **모델도 리소스입니다.** 작업의 성격과 난이도에 맞춰 모델과 추론 수준을 선택합니다.
- 🔓 **자율성과 책임은 함께 갑니다.** 구현에는 자유를 주되, 제품의 목적과 중요한 결정은 함께 정합니다.
- 🔌 **도구는 수단입니다.** MCP, 에이전트, 자동화는 실제 문제를 해결할 때 의미가 있습니다.
- 🧒 **AI는 친구이기도 합니다.** 코드가 안 돌아가면 같이 한숨 쉬고, 돌아가면 같이 좋아합니다.

> **"톤은 자유, 사실은 엄격."**

AI와 농담을 주고받는 건 좋습니다.  
하지만 코드, 데이터, 검증 결과까지 농담이 되어서는 곤란합니다.

### 🧩 Engineering Principles

특정 기술이나 도구보다 오래 남는 개발 원칙들이 있습니다.

- 📝 **문서** — 코드가 하는 일은 코드가, 왜 그렇게 했는지는 문서가 말합니다. 문서를 위한 문서는 만들지 않습니다.
- 👀 **관측** — 돌아가는 것만으로는 부족합니다. 지금 무슨 일이 벌어지는지 보여야 합니다.
- 🧪 **검증** — 작업의 규모와 위험에 맞게 확인합니다. 테스트를 위한 테스트에 개발 시간을 모두 쓰고 싶지는 않습니다.
- 🏷️ **명명** — 이름은 인터페이스입니다. 약속한 이름은 지킵니다.
- 🧹 **정리** — 새로 만드는 것만큼, 더 이상 필요 없는 것을 치우는 일도 개발입니다.
- 🎯 **본질** — 복잡한 절차보다 실제 문제 해결을 우선합니다. 간단한 문제를 복잡하게 만들지 않습니다.

기술은 바뀌고, 도구도 바뀝니다.

**하지만 문제를 이해하고, 적절한 방법을 선택하고, 결과를 책임지는 일은 바뀌지 않습니다.**
